# ThinkSmart View front camera (Linux port notes)

> Engineering log from the original bring-up (2026-11-09), kept for reference. Paths such as `/usr/local/lib/tsv-camera`
> refer to the device; build steps here are superseded by `build/30-build-camera-kernel.sh` and `build/31-build-libcamera.sh`.

## Identified 2026-11-09: Samsung S5KC505A
- CCI master 0 (Linux i2c-3 with the probe DTB), 7-bit address **0x37** (8-bit 0x6E), 16-bit register addresses.
- Chip ID: reg 0x0000 = **0x5034** (word). Matches the vendor sensor lib `libmmcamera_s5kc505a.so`
  (sensor_lib: name "s5kc505a", slave 0x6e, id reg 0x0000, id 0x5034); copy saved here.
- Stock Android slot `qcom,camera@0`: MCLK0 = GPIO26 (24 MHz), reset = GPIO40, standby = GPIO39,
  ext LDO enables GPIO118 (vdig) / GPIO119 (vana); supplies cam_vio = L6 1.8 V, cam_vdig = L2 1.2 V,
  cam_vana = L17 2.85 V; CSIPHY/CSID 0; mount angle 270. Slot camera@2 (MCLK2/GPIO28, reset 131,
  standby 132) had nothing on the bus.
- No mainline driver exists. A V4L2 driver needs the mode/init register tables from the vendor lib
  (plus MIPI lane count / link frequency), then a DT sensor node + CAMSS csiphy0 endpoint.

## Probe method (no kernel rebuild)
`tsv-camprobe.dts` = stock DTB + CCI enabled, MCLK0/2 added as CCI clocks (24 MHz while the CCI is
runtime-active), MCLK pinmux, L2 1.2 V, L17 always-on. Then from userspace:
`echo on > /sys/bus/platform/devices/1b0c000.cci/power/control`, `gpioset -z 118=1 119=1 39=1 40=0`,
then 40=1, and `i2ctransfer -y 3 w2@0x37 0x00 0x00 r2`.
On the device: /boot/camprobe.dtb (probe), /boot/apq8053-lenovo-cd-18781y.dtb.orig (stock); the stock
DTB is the active one again (takes effect on next boot).

## Progress 2026-11-09 (evening)
- Register tables extracted (`driver/s5kc505a_regs.h`): global init (vendor @0x6e20, 10 ms after first write) + modes
  2608x1960, 1304x980, 1936x1096, 1296x736, 640x490. Sensor: SMIA 1.0 map, CSI-2 D-PHY, **2 lanes**, RAW10
  (0x0111=2, 0x0112=0x0a0a, 0x0114=1). 0x0820 = per-lane Mbps (640x490: 258, 1296x736/1936x1096: 858, full/binned: 960).
- `stream-test.sh` (userspace I2C): sensor streams — frame counter 0x0005 increments. Register tables are correct.
- `driver/s5kc505a.c`: out-of-tree V4L2 driver; builds against the msm8953-mainline v7.0.9-r0 tree (reproducible chain: build/30-build-camera-kernel.sh)
  (pmaports source tag v7.0.9-r0, device config, LLVM=1, KBUILD_MODPOST_WARN=1; no modversions).
  Probes OK ("S5KC505A (id 0x5034) ready"), CAMSS registers /dev/media0 + /dev/video0-5.
- `tsv-camera.dts` (generated by `mkcam.py` from the stock DTB): sensor on CCI bus 0 @0x37, GPIO-switched
  cam_vana/cam_vdig fixed regulators (GPIO119/118 behind L17/L2), CAMSS port@0 (CSIPHY0) 2 lanes. ACTIVE on the device
  (/boot/apq8053-lenovo-cd-18781y.dtb; stock = .dtb.orig). Module is NOT auto-loaded: /usr/local/lib/tsv-camera/s5kc505a.ko
  (modprobe v4l2-cci v4l2-fwnode v4l2-async first, then insmod).
- BLOCKER: stream-on fails in CAMSS: "gcc_camss_csi0phytimer_clk status stuck at 'off'" -> "Failed to power up pipeline: -16".
  Pipeline used: csiphy0 -> csid0 -> ispif0 -> vfe0_rdi0 (/dev/video0, pgAA 640x490). Next: find why the CSIPHY0 timer
  branch won't enable (GDSC/ordering/known msm8953 camss issue; compare with msm8953 phones that stream upstream).

## FIRST FRAMES 2026-11-09 22:07
- Root cause of the CAMSS failure: on MSM8953 the CSIPHY timer clock at 100 MHz (sourced from GPLL0_DIV2) never
  turns on ("gcc_camss_csi0phytimer_clk status stuck at 'off'"). Starting the timer table at 200 MHz (GPLL0 /4)
  fixes it: `driver/camss-8953-phytimer-200mhz.patch` (camss.c, csiphy_res_8x96 timer rates; NB the 8x96 table is
  shared with MSM8996, so an upstreamable fix needs an 8x53-specific CSIPHY resource table). Powering the VFE GDSCs
  first was tested and is NOT needed (`camss-8953-vfe-pd-UNNEEDED-test.patch`).
- Patched module: `driver/qcom-camss-tsv.ko` (on device: /usr/local/lib/tsv-camera/qcom-camss-tsv.ko). Not persistent:
  after a reboot the stock qcom_camss is loaded; swap with `rmmod qcom_camss && insmod .../qcom-camss-tsv.ko`.
- `capture-test.sh` (on device in /usr/local/lib/tsv-camera/) captures packed RAW10 (pgAA) via
  csiphy0 -> csid0 -> ispif0 -> vfe0_rdi0 -> /dev/video0.
- Bayer order **GRBG** confirmed (diagonal sites equal; R > B under warm light). Black level 64 (10-bit).
  Image needs 90 deg rotation (mount angle 270). Auto exposure/gain/white balance not implemented yet: indoor night
  scene needed exposure 4400 lines (VBLANK 4000) and analogue gain 512 (16x).
- `render.py raw W H ORDER` = quick unpack/demosaic/WB preview; `frame-wb-rot.png` is the first image.

## Image quality (2026-11-09 22:18)
- Orientation: rotate 270 deg clockwise (= 90 CCW) for an upright image (user-confirmed; mount angle 270).
- Best still so far: `tsv-camera-1304x980.png` via `develop.py` — 1304x980 2x2-binned mode (full field of view),
  VBLANK 6000 (~8.8 fps), exposure 6900 lines, analogue gain 384 (12x), 12 frames averaged, bilinear demosaic,
  gray-world WB (gains R 1.26, B 3.17 under warm room light), gamma 2.2. The 1936x1096 mode is a centre CROP.
- Driver quirk: set_fmt resets the exposure range from the default VBLANK, clamping exposure; set controls AFTER the
  media-ctl format setup. (Fix: compute exposure max from the current VBLANK in update_blank.)
- libcamera 0.7.1 (simple pipeline + soft ISP) works: `cam -l` lists "Internal front camera". Issues:
  - it picks /dev/dma_heap/reserved (tiny CMA) and fails on large buffers; hiding that node makes it use
    /dev/udmabuf, which works (1920x1080 ABGR8888 captured). Proper fix: system dma-heap in the kernel, a larger CMA,
    or a udev rule.
  - soft AGC changes exposure only, never gain: libcamera has no CameraSensorHelper for s5kc505a (gain = code/32,
    linear). Adding one (plus a sensor-properties entry) means rebuilding libcamera.

## Persistent + streaming (2026-11-09 22:56)
- Persistent on the TSV (survives reboot, verified): `/lib/modules/7.0.9-msm8953/updates/{s5kc505a,qcom-camss}.ko`
  + depmod; camera DTB as /boot/apq8053-lenovo-cd-18781y.dtb (stock: .dtb.orig); libcamera 99990.7.1-r1 with
  `libcamera-0004-ipa-libipa-add-s5kc505a.patch` (CameraSensorHelper: gain = code/32, black level 4096; sensor

  CAUTION: a pmOS kernel upgrade replaces the DTB and invalidates the modules; a libcamera upgrade drops the helper.
- Driver: default mode 1304x980 (2x2 binned, full FoV); modes report crop rectangles; default 10 fps
  (VBLANK sized so AE can expose up to 100 ms), default exposure = max, gain 4x; mode change resets VBLANK/exposure.
- Stream: `mc-camera` (panel repo deploy/usr/local/bin) = libcamerasrc 1024x768 -> rotate 90 CCW -> JPEG q60 ->
  multipartmux, run as user `tsvcam` (video group => libcamera uses /dev/udmabuf, not the tiny root-only CMA heap).
  master-control: view kind "screen" with `stream = "camera"`, tile TSV page "Camera"; `/device/tsv/camera`.
  ~10 fps, ~70 KB/frame, ~14% total CPU (about 1.1 of 8 cores) only while viewed; AE/AWB settle in ~5-10 s.
